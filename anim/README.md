# 宣传动画

一段 34 秒的产品动画：从标题起手，一个玻璃窗口浮现，侧栏按月分组滑入，编辑器逐字打出
Markdown，右侧预览同步渲染，块级公式淡入、顶栏亮起「已保存」，五条卖点字幕依次落定，
最后收在 logo 与标语上。

---

## 一、方案选型

动画有三种主流做法，逐项对比后选了第三种。

| 方案 | 工作方式 | 优点 | 局限 | 本项目 |
| --- | --- | --- | --- | --- |
| **Lottie** | After Effects 导出 JSON，`lottie-web` 在页面里播放 | 体积只有几十 KB、纯矢量、任意缩放不糊、可交互 | 只产出 JSON 播放器，**不产出视频文件**；文字排版、公式、玻璃模糊都做不了；必须有 AE 源文件 | 不适用：本机没有 AE，也没有设计稿 |
| **Remotion** | React 组件即动画，时间轴驱动，直接渲染 MP4 | 数据驱动、可批量出片、生态成熟、产物即视频 | 需要 Node + React + 一整套依赖；商用按席位收费；为一个短片引入构建链，与这个项目"零构建、零 node_modules"的气质直接冲突 | 不适用：杀鸡用牛刀 |
| **HTML/CSS 时间轴 + 无头浏览器逐帧 + ffmpeg** | 页面里写 `seek(t)`，把每一帧的状态算出来；用 CDP 逐帧截图；ffmpeg 编码 | 零额外依赖（Edge 自带、ffmpeg 单文件）；**能直接复用项目自己的设计令牌、字体和 KaTeX**；同一 `t` 永远得到同一帧，可复现 | 逐帧渲染慢（1032 帧约 10 分钟）；动效要手写代码，没有时间轴软件可拖 | **采用** |

选它的三个理由：

1. **视觉一致性是硬指标**。片子里的 `--ink #07080c`、玻璃渐变、琥珀色 `#f0b46a`、
   JetBrains Mono、KaTeX 公式，全部来自 `static/style.css` 与 `static/vendor`，不是照着截图重画的。
   换成 Lottie 或 Remotion，都得把这些重新实现一遍，且做不出 `backdrop-filter` 的玻璃质感。
2. **不引入新工具链**。这个项目连 `node_modules` 都没有，为一段宣传片装 Node 不划算。
3. **可复现**。改一句文案、调一个时间点，重跑一条命令就出新片；不存在"源文件在某台机器上"的问题。

## 二、成品规格

| 项 | 值 |
| --- | --- |
| 文件 | `diary-promo.mp4` |
| 分辨率 | 1920 × 1080（16:9） |
| 帧率 | 30 fps，共 1032 帧 |
| 时长 | **34.4 秒**（末尾定格约 1.2 秒） |
| 编码 | H.264 / yuv420p / CRF 18 / `+faststart` |
| 音轨 | AAC 192 kb/s 立体声，纯音乐：合成的环境铺底，−16 LUFS，真峰值 −3.9 dBTP |
| 源文件 | `scene.html`（动画本体）、`render.py`（渲染）、`audio.py`（配乐） |
| 无音轨版 | `diary-promo-silent.mp4`（`audio.py` 首次运行时自动备份，不入库） |

### 加长版的时长分配

从 17 秒版扩到 34.4 秒，不是把每段等比例拉长，而是**按信息密度重排**——
需要观众读字的段落（打字、字幕）放慢最多，纯氛围段落（开场、收尾）给足呼吸：

| 段落 | 17s 版 | 34.4s 版 | 调整逻辑 |
| --- | --- | --- | --- |
| 开场标题 | 1.6s | 3.7s | 标题字距收拢放慢一倍，第一印象立得住 |
| 窗口浮现 | 1.1s | 2.4s | 模糊→清晰的过程拉长，玻璃质感才看得见 |
| 侧栏滑入 | 1.5s（130ms/条） | 3.2s（320ms/条） | 每条错峰翻 2.5 倍，读得出「按月分组」 |
| 打字 | 3.8s（约 40 字/s） | 8.6s（约 19 字/s） | 打字速度减半，看得清逐字过程；内容加一行引用 |
| 公式 + 已保存 | 1.9s | 3.0s | 新增「已保存」细节：绿点脉冲 + 文字淡入 |
| 卖点字幕 | 3 条 × 1.8s | **5 条 × 约 2s** | 加「双主题」「数据归你」两条，每条停得更久 |
| 收尾 | 2.6s | 2.2s + 1.2s 定格 | 节奏基本不变，尾部定格加长 |

## 三、文案

**标题**

> Diary

**标语**

> 每天写一点，公式也在里面

**说明文字**

> 本地优先的 Markdown 日记 —— 实时 LaTeX、全文搜索、玻璃日历、深浅双主题。
> 一天一个 `.md` 文件，不要账号，不走云端，没有遥测。

**片中字幕（依次出现，每条约 2 秒）**

1. 一天一页 Markdown
2. LaTeX 边打边渲染
3. 全文搜索 Ctrl+F
4. 深色 · 浅色 · 两套主题
5. 100% 本地 · 数据归你

**收尾署名**

> github.com/Enkrid-Rao/diary

**配乐**：成片是纯音乐，没有旁白。音乐按和弦进行合成、长度与画面严格对齐，
结构与电平见 [`sound.md`](sound.md)；要加旁白的话那里也留着一份十句文案与开关。

## 四、视频简介

- **用途**：仓库首屏展示、Release 说明里的动图替代品、项目介绍页 hero、演示开场。
- **时长**：34.4 秒。前 3.7 秒完成「标题 + 窗口浮现」，不看后面也能记住是什么；
  30 秒以上适合「认真讲一件事」的场合（落地页、B 站、演示片头）。
- **风格**：暗色玻璃 + 琥珀强调，极光缓慢漂移，运动曲线统一 ease-out-quint，没有弹跳和炫技；
  字幕克制、只留五行卖点，每条停足 2 秒。整体语气跟应用本身一致——安静、克制、可用。
- **适用场景**：
  - GitHub 仓库首页（MP4 可直接拖进 README，或转 GIF/WebP 预览）
  - 产品落地页首屏
  - B 站 / YouTube 的短片位
  - 演讲或录屏演示的开场片头

## 六、声音

画面是逐帧算出来的，声音也是算出来的——没有素材库、没有版权问题，重跑一条命令就能复现。
成片是纯音乐，没有旁白：34 秒全靠一段环境铺底撑，所以比"垫在人声下面"的版本多了两层结构。

**配乐**是合成的，不是下载的。四段和弦 Am9 → Fmaj7 → Cmaj7 → G6/9 各约 8–9 秒、
相邻交叠 2.2 秒；每个音用基频加六个谐波叠出弦乐质感，左右声道各偏 1.6 音分做宽度；
高八度的泛音层从 9 秒起慢慢打开、24 秒最亮、32 秒收回；上面撒十九颗很轻的钢琴点音，
落在当前和弦音上；整体过一次 2.2 秒的卷积混响，再切到 42 Hz – 7.6 kHz。

**起伏**按画面写死了一条音量曲线：开场只留低频铺底（−24.6 dBFS），打字段稳定在中段（−20.6），
字幕段最满（−19.0），收尾收干（−28.2）。整条统一到 −16 LUFS、真峰值 −3.9 dBTP。

全套参数与改动方式见 [`sound.md`](sound.md)。旁白的代码路径也留着——`audio.py build --voice`
会把十句旁白合进来，音乐在开口时自动下压 4 dB；默认 `build` 只出纯音乐。

## 七、重新渲染

```bash
# 画面
python anim/render.py                                              # 全片 34.4s / 30fps
python anim/render.py --from 0 --to 4 --fps 12 --out preview.mp4   # 只渲染一段试看
python anim/render.py --frames-only                                # 只出帧，不编码

# 声音（合在成片上，视频流不重编码）
python anim/audio.py build                                         # 纯音乐 → diary-promo.mp4
python anim/audio.py build --voice                                 # 加上十句旁白
python anim/audio.py probe                                         # 只报每句旁白实测时长
```

依赖：系统自带的 Edge（用它的 CDP 逐帧截图）+ `imageio-ffmpeg`（`pip install imageio-ffmpeg`，
自带 ffmpeg 二进制，不需要单独装）；配乐另需 `numpy` 与 `scipy`，要旁白再加 `edge-tts`。
`audio.py` 首次运行会把当前成片备份成 `diary-promo-silent.mp4`，之后每次只替换音轨。

渲染过程中间帧写在 `anim/frames/`（复用同一个目录、逐帧覆盖写入，不整目录删除），编码完成后保留，
可以随时手动清掉。旁白分句缓存在 `voice/`、混音中间文件在 `build/`，都可删。

## 八、封面

投稿用的封面和动画共用同一套颜色、字体与玻璃质感，由 `cover.html` 排版、`cover.py` 渲染。
页面里所有尺寸都用 `--u` 等比缩放（1146×717 时 `--u = 1`），所以 16:10 和 16:9 共用一套布局。

| 文件 | 尺寸 | 用途 |
| --- | --- | --- |
| `cover-2292x1434.png` | 2292 × 1434（16:10 @2x） | B 站投稿（要求 ≥ 1146×717，这里留了 2 倍余量） |
| `cover-1146x717.png` | 1146 × 717（16:10） | 平台要求的最小尺寸 |
| `cover-1920x1080.png` | 1920 × 1080（16:9） | 横版通用：YouTube、落地页、仓库头图 |
| `cover-2400x1800.png` | 2400 × 1800（4:3 @2x） | 4:3 场合（公众号头图、知乎、课程封面） |
| `cover-1200x900.png` | 1200 × 900（4:3） | 4:3 的最小尺寸 |

版面：左边是标题、标语与三个卖点，右边一张应用预览的切片——截自 `docs/01-main-flat.webp`
的预览区，旋转 1.6°、左侧加渐隐，让裁切看起来是有意的而不是切坏了。

宽高比不同会自动换气口：16:10 / 16:9 按宽度取基准、卡片留边；4:3 及更窄的画幅按高度取基准，
卡片改绝对定位、向右出血 38px，文字列收窄到 44%，标签字号也随之收一档避免换行。

```bash
python anim/cover.py                    # 三个尺寸一起出
python anim/cover.py --size 1146x717    # 只出某一个
```

依赖与渲染动画相同（系统 Edge + 无头截图），不需要额外安装。
